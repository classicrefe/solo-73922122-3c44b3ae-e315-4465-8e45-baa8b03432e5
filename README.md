# 涂层实验室 · 膜厚分档换表（烘烤前后两张现行表）

质检员上传两张更正后的膜厚分档表，页面预览哪些现行有效试片能保留；
确认后两张新表同时生效，落选试片标记「待复核」。

## 启动（Docker Compose）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

- SQLite 文件位于命名卷 `coating-data` 的 `/data/coating.db`，重启后保留。
- 换端口：`COATING_PORT=9000 docker compose up --build`。
- 首次启动自动写入演示数据：60 条试片记录 + 一张现行分档表。
- 页面底部「重置演示数据」可反复演示换表。

## 不使用 Docker

```bash
python3 -m pip install -r requirements.txt
COATING_DB=./data/coating.db python3 -m app          # 开发服务器
# 或：gunicorn --bind 0.0.0.0:8000 --workers 1 --threads 4 'app.__main__:app'
```

## 页面演示流程

1. 首页「现行分档表」显示当前烘烤前/后两表、各档件数与已占数。
2. 「上传两张更正表并预览」：可直接粘贴，也可选择 UTF-8 文本文件。
   格式：每行 `下限-上限 件数`（闭区间、整数微米），如 `0-25 12`。
   也接受 `21..40 12`、`41 60 8`、`61,80,3`。
3. 预览页显示最多可保留哪些现行有效记录、每档保留数/余量、落选原因。
4. 点「确认换表生效」：两张表同时启用，落选记录转为待复核。
   若预览后已有另一次换表生效，确认会被拒绝并要求重新预览。

演示用的一组更正表（首页预填）可保留 53 条，7 条落选
（4 条读数越界 + 3 条档内件数已满）。

### 输入与校验规则

- 每张表各档闭区间互不重叠；两张表总件数必须一致。
- 试片记录：每行 `试片号 烘烤前 烘烤后`，按提交顺序登记；唯一试片号；
  最多 60 条（应用层与 SQLite 触发器双重限制）。
- 同一试片只占前后表各一档；每档保留数不超过该档件数。

### 保留规则

在「保留数最大」的前提下，按登记顺序做字典序比较：
最早出现分歧的记录优先保留。距离说明：如果保留第 1 条会让总数从 2 降到 1，
则放弃第 1 条，保留能凑满最大数的更晚记录。
实现为容量化二分匹配（Dinic 最大流），逐条固定决策并在剩余图上重算最大流。

### 一致性保证

- 预览与确认都在 `BEGIN IMMEDIATE` 事务里执行，并发确认会串行化。
- 确认时校验预览代次（generation）、试片记录指纹和预览时的保留清单；
  任一不符即拒绝，原表与全部记录状态不变。
- 所有写入（新表、状态更新、审计行、指针、批次状态）在同一事务中，
  任一步失败整体回滚。

## 测试

```bash
python3 -m pytest -q
```

覆盖：格式/重叠/总件数校验、60 条上限、闭区间边界、字典序最优性与
最大流对照的随机校验、越界与件数不足的落选原因、待复核不参与保留、
确认幂等性、过期预览冲突、记录变更冲突、写入失败整体回滚、
并发确认串行化、演示数据的 53/7 结果。

## 目录

```
app/
  db.py          SQLite schema（试片、批次、分档、审计、状态代次）
  validation.py  两张表与试片记录的解析/校验
  selection.py   容量化二分匹配与字典序保留选择
  service.py     预览、确认、当前表查询、演示种子
  web.py         Flask 路由
  templates/     页面
tests/           单元 + 路由 + 并发测试
```
